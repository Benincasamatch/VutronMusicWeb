## 本次发现并修复

1. **客户端请求饱和会误停播放器和实时同步。** 外部请求和内部生命周期任务现使用独立、有界的准入配额，同时保持同一 FIFO 执行顺序。只合并相邻的进度采样；心跳和进度广播最多各有一个待执行任务。真实内部错误仍停止服务，而不是被当成普通限流忽略。
2. **Windows 路径别名被错误识别成符号链接。** 检查真实祖先组件中的 symlink / junction，而不是直接比较 realpath 和字符串路径；保留加载时的目录约束和文件身份校验。
3. **Vite 存在两个版本，导致插件类型不兼容。** 用根级 overrides 统一到已经选定的 7.3.6，没有通过类型断言或关闭严格检查掩盖错误。
4. **Fastify 路由配置弃用警告。** `maxParamLength` 改为通过 `routerOptions` 传递。
5. **`npm start` / systemd / `npm run admin` 全部起不来（发布阻断项）。** tsup 的 `removeNodeProtocol` 默认把 `node:sqlite` 改写成 `sqlite`，构建产物运行时报 `ERR_MODULE_NOT_FOUND`；开发模式走 tsx 掩盖了它。已在 `apps/server/tsup.config.ts` 设 `removeNodeProtocol: false`，并实测 `dist/index.js` 能启动、`dist/admin.js` 能进入自身校验。
6. **mpv 崩溃后不可恢复且零日志。** 驱动永久 `broken`、丢弃子进程输出，只有重启能救。现记录失败原因（含脱敏后的 mpv 输出尾部），并允许下一次 `play` 重建驱动一次，成功则广播 `player.recovered`，失败保持显式错误态。
7. **设备回退不可见。** 设备名写错或设备消失时 PipeWire 会静默改道，界面仍显示 playing。现观察 `audio-out-detected-device`，与显式配置的设备不符时在快照的 `player.warning` 中持续告警（`auto` 不算不符）。（该属性在 mpv 0.39 上并不存在，第二轮改用 mpv 自身的错误输出，见第 15 条。）
8. **崩溃后需人工清锁、孤儿 mpv 继续出声。** 现仅在锁记录的属主**确已消失**时接管锁，并按 uid 与私有 socket 目录回收残留 mpv；属主存活 / 记录不可读 / PID 被重用一律 fail closed。systemd 示例改为 `Restart=on-failure`。
9. **启动失败只有一句通用提示。** 新增 `StartupError` 标记可安全打印的消息（无文件名 / SQL / 连接细节），入口原样输出；锁、配置、数据目录等失败现在可区分。
10. **新增必填字段会让旧数据库无法启动。** `player.warning` 使旧 checkpoint 行严格校验失败；读取时先补默认值再校验，并有回归测试。
11. **依赖公告未处置。** 运行时 3 个 high 已按上表升级（fastify 5.12.5、@fastify/static 10.1.5、ws 8.22.0）；开发工具链升到 vite 7.3.6、vitest 4.1.11。曾用根级 override 强制 esbuild 版本，越过 `tsx` 的 `~0.25.0` 范围使其变为 invalid，已回退并删除锁文件重新解析，全树 0 个 invalid。`npm audit`（含开发依赖）现为 0 漏洞。
12. **手机锁屏后界面仍显示已连接。** 设备休眠会让 socket 半开：对端收不到关闭帧，页面一直保留最后一次状态。服务端每 30 秒 ping、60 秒终止无响应连接，但浏览器 JS 看不到控制帧；空闲房间本来就不广播任何快照，所以客户端也不能用“最后消息时间”判断存活。现改为：页面隐藏超过 5 秒后重新可见、或网络 online / offline 变化时重新确认会话与状态；静默看门狗只在播放时启用（播放时服务端约每秒推送一次进度，静默 12 秒即判定 socket 已死），空闲房间不会误报。
13. **重启后中断的曲目完全消失。** 原行为只保留待播队列与音量 / 静音，当前曲目和位置一并丢弃。现改为把中断的曲目恢复为**暂停**状态：状态为 paused、分配新的 playbackId、位置与时长照原样恢复，但**不装载文件、不出声**，必须由用户显式点播放；此时才装载文件并 seek 到保存位置，而不是从头重放。曲目若已不在目录中则丢弃恢复，避免展示一个永远无法播放的条目。schema 本就不允许 idle 状态携带 current，所以恢复态只能是 paused。
14. **mpv 被杀后无法自愈。** `markFailure` 在清理时用 `driver.close()` 兜底 `stop()` 的失败，而 `close()` 是终态的（`closing = true` 之后 `restart()` 直接拒绝），于是唯一的重建路径被永久关闭：再次播放返回 503，永远不会有 `player.recovered`。现改为清理失败就放弃，把回收残留子进程交给 `restart()` → `reset()`。测试替身 `FakeDriver` 当时既不模拟终态 `close()`、也不模拟"进程已死"，所以这个缺陷一直没被发现——已让它忠实建模这两种状态，回归用例在还原修复前会失败。
15. **设备回退告警从未生效。** 原实现观察 `audio-out-detected-device`，而 mpv 0.39.0 对该属性返回 property not found，失败又被静默吞掉，因此永远不会有告警。现改用 mpv 转发的日志（见第 17 条）识别回退：只在 mpv 报告"无法初始化我们配置的那个驱动"时告警，mpv 自行探测的其他驱动和 `auto` 都不算不符。警告改为只在重新开始播放时清除。
16. **孤儿回收误杀存活实例的 mpv。** 原扫描只按 uid 和共享临时目录的 `lan-mpv-` 前缀匹配，所以同账号、同 TMPDIR、不同 DATA_DIR 的第二个实例会杀掉仍由存活服务拥有的 mpv。现把 socket 目录名改为包含数据目录摘要（`lan-mpv-<12 位十六进制>-`），扫描只针对本数据目录；锁已经证明该目录没有存活属主，命中的必定是遗留进程。用摘要而非路径，是为了不让 `/proc/<pid>/cmdline` 泄露音乐库位置。注意：升级前遗留的旧前缀孤儿需要手工清理一次。
17. **mpv 的日志与错误输出实际上看不到。** 启动参数里的 `--terminal=no` 会连同 mpv 自身的 stderr 日志一起关掉，所以此前"记录脱敏后的 mpv 输出尾部"的诊断几乎总是空的，设备回退也无从判断。现通过 IPC 的 `request_log_messages warn` 让 mpv 把日志转发到私有 socket；消息只用于脱敏后的诊断尾部和回退判定，不落盘、不进入快照。mpv 若不支持该命令，会打印一条明确的降级提示，而不是静默失效。
18. **恢复态下的定位与"上一首"必然失败。** 恢复的条目在驱动里没有装载文件，但 `seek` 和"上一首（无历史）"仍直接调用驱动，于是抛错并把条目推进 `PLAYBACK_FAILED`。现改为：未装载时把偏移记在待续位置上，等用户点播放时再真正 seek。
19. **恢复位置会在一次失败后永久丢失。** `load()` 在驱动工作之前就把 `positionSeconds` 写成 0 并持久化，于是 acquire / load 的一次瞬时失败、或过程中的一次崩溃，都会把保存的 42 秒变成 0。现改为在整个恢复过程成功之前一直保留待续偏移与位置。
20. **一次启动失败会让驱动永久不可用。** `start()` 的失败分支用终态 `close()` 清理，`closing = true` 之后 `restart()` 永远拒绝，即使主机问题已经排除。现改为用非终态的 `reset()` 清理。这与第 14 条是同一类缺陷：终态清理被当成了普通兜底。
21. **把音频文件换成 FIFO 会挂死整个协调器。** `catalog.acquire` 先以阻塞方式 `open(O_RDONLY)` 再 stat，若扫描之后文件被换成没有写端的 FIFO，open 永不返回，协调器的 FIFO 链（含停服）随之卡死。现加 `O_NONBLOCK`：对普通文件的读取没有影响，非普通文件随即被 stat 拒绝。
22. **陈旧锁接管可能产生两个属主。** 接管时直接 `rm` 掉锁文件再新建：若两个进程同时判定同一把锁已陈旧，后者的 `rm` 会删掉前者刚建立的新锁，于是两个进程都认为自己是属主——同一数据目录、两个 SQLite 写入者、两个 mpv。现改为比较并交换：删除前重新读取锁的内容与 inode，只有仍是我们判定为陈旧的那一个文件才可替换，新建仍由原子的 `open('wx')` 把关；锁不是普通文件（符号链接、目录）时一律不信任。检查与删除之间仍有一段窄窗口，不引入 OS 级排他锁无法完全消除，这一点写在代码注释里而不是假装已解决。
